### **async/await**

Chaining promises with `.then()`/`.catch()` made handling async data via callbacks more readable. But now there's another way to write it!

The `async`/`await` keywords (released after ES6) offer a more concise way of writing promises:

```js
function getSomeDataWithChain() {
  fetch(someData)
    .then((response) => response.json())
    .then((data) => data)
    .catch((error) => console.log("Something went wrong. 😦"));
}

async function getSomeDataWithAsync() {
  const response = await fetch(someData);
  if (response.ok === false) {
    throw new Error("Something went wrong. 😦");
  }
  const data = await response.json();
}
```

The first function asks for promise data with `.then()` statements and handles any errors with `.catch()`. The second function does the same thing with `async`/`await`.

First, the `async` keyword is added to the function definition. Then inside the function, any operation that returns a promise (like `fetch()` and `.json()`) can have an `await` next to it. This ensures that the next operation won't start until the promise is fulfilled or rejected.

When a `response` object is made, we check if its `.ok` property is `false` (meaning the data fetch didn't succeed). If so, we throw an error with a message.

When using `async`/`await`, we can check if promise came back with an `ok` property that is `true` or `false`:

```js
async function getSomeData() {
  const response = await fetch(someData);
  if (response.ok === false) {
    throw new Error("A problem occurred while fetching the data.");  
  }
  const data = await response.json();
}
```

If `response.ok` is `false`, then it can stop the function and throw a new `Error` with a message about what happened. This is used instead of `.catch()`.

By the way, it is totally valid to stick with `.then()`/`.catch()`. The `async`/`await` keywords are just [syntactic sugar](https://en.wikipedia.org/wiki/Syntactic_sugar) that accomplish the same thing, just with different words.
